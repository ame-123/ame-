# 项目问题：预订多轮槽位丢失与进图前二次确认

## 现象

多轮对话里，用户会分句补预订信息，例如：

1. 「目的地东京，日期明天」
2. 「日期是 2026.6-10 号」
3. 「有哪些套餐供我选择」
4. 「就这个套餐，进入预定流程」

客服话术看起来已经记住东京和日期，但第 4 句仍被挡住：`booking_slots_blocked`，提示缺少目的地或套餐。一句说全（「帮我预订 2026-06-10 出发的东京五日机票酒店」）则可以进图。

## 原因

系统里其实有短期记忆，但记的是**已有行程单号**（查进度、退票），不是**新预订表单**。

进预订图前，`extract_booking_slots` 只扫**当前这一句**。上一轮抽到的东京不会写入预订槽位；最终模型能看见压缩后的聊天历史，于是把东京和日期说得很完整——那只是话术，不是后端 state。

另外：

- 「明天」不会换算成日历日期，这是刻意的，避免猜出行日。
- 「就这个套餐」原先不会绑定上一轮 `search_products` 返回的套餐名。
- 槽位齐了以后直接查可订名额、进人批，没有用户对要素点头的步骤。

这和查已有行程不同：行程单号可以走 `explicit > 页面 Runtime > session last_order_id`。新预订缺的是 Dialogue State / 表单记忆。

## 改法

在 session 里增加 `booking_draft`：

- 每轮把本句抽取合并进草稿（本句覆盖旧值）。
- 「就这个 / 这个套餐」**只允许**绑定记忆里的 `last_product_name`，且必须落在套餐白名单；没有工具结果就不填。
- 日期仍不接受「明天」；顺手兼容 `2026.6-10` 这类写法。
- 槽位齐了但本句不是一次说全：先 `booking_confirm_required`，列出目的地、日期、套餐和来源，等用户回「确认」再进 LangGraph。
- 一句说全的「帮我预订 + 目的地 + 日期」视为表单提交，仍直接进图（兼容原评测），进图后主管 HITL 不变。
- 图内 `fill_slots` 以已确认 / 已合并的 state 为准，不再用空的当前句把草稿冲掉。

确认是**用户对槽位点头**，不能替代可订名额校验和主管审批。

## 怎么验收

命令行：`python chat.py`（需 8081 mock）。按上面四句再回「确认」，应先看到确认清单，确认后才出现待人工审批。终端会打印 `booking_draft`。

单测：

```powershell
cd projects/knowledge-assistant/travel_agent/backend
$env:AGENT_COURSE_DISABLE_LLM="1"
python -m unittest tests.test_booking_draft
```

原一句说全用例 `booking-available-hitl` 仍应进入 HITL。
