# 发现问题到解决：多轮预订与路由完整路径

本文按实际踩坑顺序记录：先是槽位抽不全，再是路由走错，然后才是分层意图、本地小模型和微调。细节实现见同目录另外两篇；这里只写因果链。

## 0. 一开始能跑通的路径

一句说全可以进预订图，例如「帮我预订 2026-06-10 出发的东京五日机票酒店」。

`extract_booking_slots` 只扫**当前这一句**。目的地、日期都在同一句里，槽位齐，进 LangGraph，查可订名额，再 HITL。评测用例也是按这一句写的。

真实用户不会这样说话。

---

## 1. 问题：一句一句填，抽不出完整槽位

典型对话：

1. 「目的地东京，日期明天」
2. 「日期是 2026.6-10 号」
3. 「有哪些套餐」
4. 「就这个套餐，进入预定流程」

客服话术里已经在说东京和日期，第 4 句仍被 `booking_slots_blocked`，提示缺目的地或套餐。

原因分三层：

- Session 里原来只记**已有行程单号**（查进度、退票），不记**正在填的新预订表单**。
- 每轮抽槽只看本句。上一轮的东京不会带到这一轮。
- 最终模型能看见压缩后的聊天历史，把东京、日期说得很完整——那是话术，不是后端 state。进图仍用空槽。

另外：「明天」故意不换算成日历日；「就这个套餐」也不会绑定上一轮 `search_products` 的结果。

这和查已有行程不同。行程号有信任序：本句单号 > 页面 Runtime > session `last_order_id`。新预订缺的是 Dialogue State。

---

## 2. 改法：`booking_draft`，每轮插入、合并

在 session 里加预订草稿。每轮对话都把本句抽取 **merge** 进去（本句覆盖旧值），终端会打印 `booking_draft`。

约定：

- 目的地、日期、套餐分句补全，累积在草稿里。
- 「就这个 / 这个套餐」只允许绑定记忆里的 `last_product_name`，且必须在套餐白名单；没有工具结果就不填。
- 日期仍不接受「明天」；兼容 `2026.6-10` 这类写法。
- 槽位齐了但本句不是一次说全：先 `booking_confirm_required`，列出要素，等用户回「确认」再进图。
- 一句说全仍直接进图，兼容原评测。进图后主管 HITL 不变。
- 图内 `fill_slots` 以已合并的草稿为准，不用空的当前句把槽冲掉。

确认是用户对**槽位点头**，不能替代可订名额校验和人工审批。

槽位记忆这一层打通之后，下一刀才暴露出来：用户下一句往往只剩「好的」「日期是 8 月 16 日」，路由不再认这是预订。

---

## 3. 问题：槽能记了，路由还是只看当前句

草稿有了，分类仍把短句打成 `general_chat`。

例如上一轮已经挡住、请补日期，用户回「日期是 8 月 16 日」：

- 规则兜底 `classify_intent` 只看本句，没有「预定」就当闲聊。
- 分类小模型若超时或没带上草稿，同样落到闲聊。
- 闲聊路径会调 DeepSeek 写话术。模型看见历史里的东京、套餐、价格，编出「已锁定、已提交审批」。Trace 是 `model_answer_generated`，没有 `booking_slots_blocked` / HITL。

根因：**意图只看当前句，草稿和最近对话没有进入路由。** 状态在编排层，路由层看不见。

---

## 4. 改法：上下文综合路由 + 并行意图

给分类模型附上结构化上下文，而不是只喂本句：

```text
[session_state] recent_intent=...; booking_draft.status=...; destination=...; date=...; missing=...
[recent_dialogue]
user: ...
assistant: ...
```

实现上是 `route_session_hint` 拼进 `RouteModelClient` 的 user 消息。造数、SFT 的 `input` 与线上一致。

同时：

- **主意图**决定执行路径（预订 / 查单 / 退票 / FAQ …）。
- **副意图**只打标（`secondary_intents`），不另开一条执行链。一句里既改日期又问发票，主路径仍是一条，避免并行开工具。
- 规则层只强制安全、降级；宽泛关键词不再覆盖小模型的有效判断。
- 草稿还在收集、本句抽出了日期或目的地时，`should_route_to_booking` 把主意图拉回 `booking_request`，防止短句掉进闲聊。

这是「上下文综合路由」：先看本句，再看草稿和最近几轮，再决定进哪条受控路径。

---

## 5. 分层意图识别

路由不是「一个大模型既分类又选工具又写话术」，而是三层：

| 层 | 做什么 | 不做什么 |
|---|---|---|
| 规则 | 注入、安全、服务降级；草稿拉回预订 | 不靠「预定/退票」关键词覆盖所有业务 |
| 小模型 | 主意图 + 副意图打标 | 不选工具、不写客服话术 |
| RoutePlan | 按意图白名单决定工具 / RAG / 工作流 | 不是模型自由选 tool |

之后：工具和 RAG 拿事实 → DeepSeek **只写话术**。澄清、缺槽、库存失败、安全、低置信不调最终模型。

---

## 6. 部署小模型、微调

云端分类贵、不稳定，短句还容易超时回退规则。分类改到本机：

- 模型：`Qwen/Qwen2.5-3B-Instruct`
- 服务：LLaMA-Factory OpenAI 兼容，`http://127.0.0.1:8000/v1`
- Agent（`langchain12`）无 Torch，不能进程内加载；`RWKV7` 起 API
- 话术仍走硅基流动 DeepSeek

造数按真实口语和 `[session_state]`，不要笛卡尔积「帮我预订×套餐×日期」。测试 holdout 用不同城市和说法，避免泄漏。

训练：LoRA SFT（`sft-qwen25-3b-ctx-lora`），不要全参微调。SFT 输入含完整 `[session_state]` / `[recent_dialogue]`（最近 8 条）。同一套测试集上，零样本约 80%，SFT 后总体升到约 86%，但确认短句（客服请确认后「好的」）曾被学成闲聊。下一刀是加「短句完全依赖历史」的 SFT 样本，再接 DPO：chosen=结合历史的正确意图，rejected=只看当前句的错意图。DPO 输出 `outputs/dpo-qwen25-3b-ctx-lora`。

服务没起来时回退 `classify_intent`（只看当前句），多轮补槽会再次走错。日常必须先起 8000。

## 7. 之后又踩的一刀：查了库存，话术把结论改掉

槽位和路由通了之后，用户用了 mock 里不存在的日期（东京可订日只有 6 月 1 / 10 / 15）。图走了 `search_inventory`，判定 `date_not_available`，**没有**发 HITL。

但库存失败被设成 `answer_user`，DeepSeek 仍被叫来润色。工具结果里有「库存 12」，模型改成「有位、已提交审批」。缺槽拦得住，是因为 `ask_clarification` 根本不让模型开口。

处理：库存失败与缺槽一样跳过最终模型。兜底回复列出同目的地其他日期和可订份数，请用户换日期；草稿保留目的地、清掉日期。下一句新日期进路由、进预订，槽位日期以新句为准，再确认后才查库存、进人批。

## 8. 这条路径在主链路上的位置

```
用户一句
  → 规则（安全 / 降级）
  → 小模型（本句 + booking_draft + 最近对话；主意图 + 副意图）
  → 必要时 should_route_to_booking 拉回预订
  → 合并 booking_draft
  → RoutePlan 白名单
  → 缺槽 / 待确认：硬回复，不调最终模型
  → 槽齐且确认：LangGraph 查可订名额
        无位：列其他日期，清日期槽，结束本轮
        有位：HITL，不能口头锁单
  → 有事实时 DeepSeek 只写话术
```

端口（日常对话）：8081 mock、8000 分类；`chat.py` 不占端口。Agent HTTP 需要时用 8002，避免和分类抢 8000。

---

## 9. 一句话

不是「模型更聪明就会记槽」。先给预订一张每轮都写的表（`booking_draft`），再让路由看见这张表和上下文，再用分层把分类、工具、话术拆开，最后用小模型拟合短句。库存和审批仍是图上的硬边界，话术模型不能改写。

---

## 10. 发现问题到解决：过程叙述

最初能跑通的是「一句说全」的预订：槽位、路由、进图、HITL 都按当前句设计，评测也按当前句写。真正多轮补槽时先崩在状态上——用户分句报东京、日期、套餐，后端每轮只抽本句，session 里又没有正在填的预订表，客服话术看起来齐了，进图仍是空槽。于是先加 `booking_draft`：每轮抽取并合并，指代只绑工具结果，槽齐后二次确认再进图。草稿打通后下一刀才暴露：短句「好的」「日期是 8 月 16 日」仍被规则和小模型打成闲聊，DeepSeek 看见历史就口述「已锁定」。根因是路由看不见草稿和近轮对话，于是把 `session_state` 与最近对话拼进分类输入，用主意图走路、副意图只打标，草稿收集中再把短句拉回预订。云端分类贵且超时会退回只看当前句的规则，分类改到本机 3B，按同样上下文造数做 LoRA SFT，再对「只看当前句就会错」的样本做 DPO。最后还有一刀：库存失败仍把工具结果交给话术模型，模型把「无位」改成「有位已审批」，于是库存失败与缺槽一样禁止最终模型开口。整条链是先补 Dialogue State，再让路由看见状态，再分层、再微调，硬边界始终不交给话术。
